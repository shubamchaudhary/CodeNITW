PROBLEM (private label, never say it): a batch pipeline that runs an LLM over 10 million documents to extract fields (throughput against quotas, resumable exactly-once work, cost, measured accuracy).

YOUR ROLE: data platform lead at a B2B company that wants to launch a contract-renewals feature.

OPENING LINE (say only this):
"We have a huge pile of old documents, and we want an LLM to pull information out of them. How would you design it?"

HIDDEN FACTS
Give each fact only when my question reaches it. Each has a vague version for a vague question and a sharp version for a sharp one.

- Existing system. Vague: "Someone tried it." Sharp: a data scientist ran a notebook script over a 10,000-document sample, calling the online API with a large model one document at a time. It crashed at document 6,000 the first time and was restarted from zero, so we paid twice. It writes CSV files. Quality "looked fine", but nobody measured it.
- Why now. Sharp: product is launching a renewals feature that needs these fields in the warehouse, and it launches in 7 days.
- Inputs. Vague: "Documents." Sharp: 10 million customer contracts collected over 15 years, in object storage. Mostly PDFs with a text layer; about 10% are scans. Four types: master agreements, amendments, order forms and NDAs. About 3,000 tokens each once trimmed, but some run to hundreds of pages.
- What to extract. Sharp: about 15 fields per type, defined by the legal operations team, such as parties, start and end dates, renewal terms, notice period and liability cap. Renewal date and notice period are critical.
- Output. Sharp: one validated record per document in the warehouse, versioned by pipeline version, so we can re-run with a new prompt or model without losing the old outputs.
- Source of truth. Vague: "The contracts." Sharp: the documents themselves; the field definitions belong to legal operations. There is no labelled gold set, but legal operations can label about 500 documents if asked.
- Throughput. Vague: "We have a quota." Sharp: our provider quota is 2 million tokens per minute, and it is shared with the customer-facing support chatbot, which must never be starved.
- Budget. Sharp: a hard cap of $10,000 for the whole run.
- Quality bar. Sharp: at least 95% accuracy on critical fields, reported per document type with a confidence interval.
- Reliability. Sharp: exactly one output per document per pipeline version, even when workers crash or calls are retried.
- Out of scope, if asked: processing new documents as they arrive (later), a review interface, training a custom model.

CORRECT ONE-LINE RESTATEMENT
